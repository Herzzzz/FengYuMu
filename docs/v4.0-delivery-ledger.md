## 二、本轮新增完成

### 1. 窗口锁定层（架构第一层）

`src\MapleWindowTracker.cs`（488 行）

- 多证据识别：进程名 + 窗口标题 + 窗口类 + 可见性 + 拥有者 + 客户区尺寸
- 全屏客户端拒绝翻译；`TryGetCaptureBounds` **禁止回退全桌面扫描**
- 1 秒低频轮询；DPI / 尺寸变化重绑；句柄丢失重新锁定
- **零 OCR、零联网、零内存访问**；只申请 `PROCESS_QUERY_LIMITED_INFORMATION` 只读权限

### 2. 捕获来源切换

F8 与 F9 从「前台窗口」改为「锁定客户端客户区」；重绑时清除过期标签。

### 3. 快速首显

主 OCR 完成即发布**高置信度**标签，不再等全部面板复核。

### 4. 置信度体系

`LabelConfidencePolicy`（精确 70 / 模糊 35 / 截断 −25；高 ≥70、中 ≥50）；
`MergeLabels` 改为**置信度优先**，低置信度结果不再覆盖正确首显。

### 5. 双渲染与原位替换

`LabelRenderMode` + 背景**标准差**判均匀度（>26 回退卡片）；
擦除区严格取自 `SourceBounds`，**不随译文变宽**，不遮动态数值。

### 6. 性能指标

`last_run.txt` 新增「首次可见耗时」「最终收敛耗时」「置信度分布」「匹配来源」
「可无缝标签」。

### 7. 坐标换算统一

28 处重复的内联换算 → `ToOverlayX` / `ToOverlayY` 单一来源。

### 8. 死代码删除

引用计数为 0 后删除，每项均在删除后编译通过：

| 删除内容 | 证明 | 替代 |
|---|---|---|
| `LabelConfidencePolicy.StageBonus` | 全仓引用 = 0 | 阶段质量作参数传入 |
| `LabelConfidencePolicy.FastPaintThreshold` | 全仓引用 = 0 | `IsTrusted` |
| `LabelConfidencePolicy.MayPaintImmediately` | 全仓引用 = 0 | 无（首显用 `IsTrusted`） |

### 9. 测试链路修复（环境相关，非测试放宽）

- `tests\Load-TestAssembly.ps1`：本仓库位于含中文目录的路径，CLR 会把程序集判为
  「远程源」而拒绝加载。先试 `LoadFile`，仅在该错误时改用 `UnsafeLoadFrom`。
  同一程序集、同样断言。
- `tests\Start-ProductExe.ps1`：改经 `CreateProcess` 启动产品，避免 Windows
  附件管理器对每次启动弹出「发布者未知」确认框。未修改任何系统安全设置。

### 10. 新增回归用例

- `tests\logic-window-tracker.ps1`：证据规则、全屏拒绝、双向状态契约、安全边界
- `tests\logic-overlay-dual-rendering.ps1`：纯色启用无缝、渐变回退卡片、
  越界/退化区域拒绝、擦除区取自 `SourceBounds`

### 11. 修复桌面弹窗（会打断玩家）

根因：产品更新流程收尾会启动新装的程序，而更新测试用占位文件驱动该流程，
ShellExecute 触发 Windows 安全提示。新增 `AutomationPolicy.SkipGuiRestart`
（读 `FENGYUMU_AUTOMATION=1`），自动化时不启动 GUI，真实升级行为不变。
另新增 `tools\Invoke-AutomatedRegression.ps1` 统一测试入口。详见验证笔记第五节。

### 12. 待命开销修复

单次轮询 56.71 ms → **0.72 ms**；待命占空比 5.67% → **0.072%**。
根因是逐个顶层窗口调用 `Process.GetProcessById`；改用
`QueryFullProcessImageName` 单次只读调用。

### 13. 翻译路径取消模态框

遇到全屏/未找到窗口时不再弹模态框抢走游戏焦点，改为屏幕提示 3.5 秒自动消失。

---

### 14. 低置信度标签的二次 OCR 复核

`ShowTranslationAsync` 在规划面板复核目标时，额外把**未被置信度策略信任**的标签
区域排入复核队列：只收带实测源区域的标签，**最多 2 个**以防单帧 OCR 工作量失控，
复核结果仍由同一套置信度规则裁决——读好了就替换弱标签，没读好则原样保留。
所有标签都已被信任时，这段逻辑不做任何事，因此不增加常态开销。

## 七、过程中发生的事故（如实记录）

对 `MapleOverlay.cs` 做坐标批量替换时，PowerShell 数组缺逗号导致
`Replace(char, char)` 逐字符执行，把 `T` 全部替换成 `o`，文件被破坏。
随后用 `git checkout` 恢复，又因该命令丢弃工作树改动而**丢失了全部未提交改动**，
据此重新构建。

重新构建引入了三处**静默退化**（能编译、测试通过，但设计意图已变），
后续逐轮审计才发现：

1. 快速首显丢失按置信度过滤 → 低置信度结果被当作定论提前显示
2. `IsTrusted` 变成零调用死代码
3. 7 个标签创建点中仅 1 个设置 `SourceBounds` → 双渲染几乎无法生效

**已采取的防复发措施**：该文件只用逐条 `edit`（不再脚本批量替换）；
改动测试断言前先跑 `Parser::ParseFile` 验证语法；每步改动后立即编译；
生成备份后必须执行 `git apply --check` 验证其可用。
