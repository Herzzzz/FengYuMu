## 已确认的源码机制

1. src/SimpleFusionComposition.cs / PrepareSimpleFusionAsync：
   每个label单独重建surface、调用FitSimpleFont；没有同一面板正文共享的字号计划。
2. 同文件 / FitSimpleFont：
   起始字号 clamp(SourceHeight,8,26)，放不下每次减1像素，直到8；返回第一个完整容纳该块文本的字号。代码允许缩到8px，不代表已量测出用户图里的确切字号。
3. src/TextSurfaceReconstruction.cs 及 SimpleBackgroundFill.cs：
   SourceHeight来自擦除行矩形高度的中位数；这是OCR/擦除几何，不是经过字体度量校准的字号。
4. src/SkillSectionOverlay.cs：
   简介槽可能按区域高度人工分成若干source rows。合成擦除行不能当真实字高证据。简介、当前级、下一级分别成label，会各自缩小。
5. 简介slot还有20px上限，人物field有18px上限；任务正文在QuestJournalComposition中另用14..20px、另一字体族和分页。不同路径的排版标准不一致。
6. 尚无本次同帧诊断，不能断言所有英文残留都由字号引起。必须区分没识别、没匹配、准备失败、未绘制和擦除遗漏。

## 通用优化方案

A. 将文字样式规划与擦除/布局几何分开：
- 在同一已确认面板内，先建立一次PanelTypographyPlan（或等效结构），再排各块。
- 技能简介、消耗、当前级效果和下一级效果共用正文基准字号及行距。标题可稍大，只允许预定义层级；不能为了齐字号把标题也压到正文大小。
- 同类装备字段、人物字段、任务正文使用共享的度量原则；无需把所有不同角色和应用UI控件强制成一个字号。
- 仅以可靠的原始文字行估计游戏尺度：剔除图标/孤立数字/短碎片及人工合成擦除行，采用稳健统计，结合所选字体的字身/行高关系校准；不直接把OCR包围框高度当Font.Size。
- 明确原始截图物理像素、OCR预处理比例、游戏界面比例和Windows DPI转换，尺度只转换一次。不能依据录屏缩略图来设置字号。

B. 保持字号，优先解决容纳：
- 先测量同面板的有效内容区，按语义块统一换行和分配行距；保护图标、分隔线、数量、实时数值、下方等级段和邻近窗口。
- 禁止各label通过不断缩到8px来满足fitted==text.Length。基准字号由面板样式决定，不能由该条译文长短独立决定。
- 100%参考画面可先用约14逻辑像素正文作为实机样例，候选阅读下限约12逻辑像素；按实际游戏尺度、字体和Windows显示校准，不能硬编码所有分辨率14物理像素。
- 长内容先使用已测得的面板空白宽高换行；仍不足时，给出面板级溢出方案，复用现有阅读/分页思路并保留当前级/下一级可见。不允许静默截断、极小字、越界覆盖，或把当前/下一级整段挤掉。
- 若安全容纳条件不足，明确记录失败原因并保留对应原文；擦除和绘制必须一起提交，避免原文先消失、中文没画出。不要借此增加多轮识别或通用重试层。
- 不改变用户选定字体来绕过度量问题；同一面板沿用统一字体来源和度量方法。

C. 稳定性及英文残留：
- 同一截图重复F8、同一内容OCR轻微抖动、当前/下一级不同文本长度，不应导致正文忽大忽小。
- 样式缓存必须带面板身份和尺度；换技能、换窗口或缩放变化不能套用旧面板样式。
- 对截图可见的残留英文按分区统计 recognized / matched / prepared / painted / preservedReason。不能把原文存在都报成字号bug，也不能靠放大中文遮住原文。
- 不添加特定技能、任务、道具、职业、玩家或服务器运行时分支；不改聊天分类、OCR模型和AI请求逻辑。

## 验收要求

1. Windows原生字号和字体度量：
   用同一提交、同一EXE回放用户技能图；分别给出简介、等级标签、当前效果、下级效果实际Font.Size/Font.Unit、行距、内容区及溢出处理。原图未取得或未跑则标UNVERIFIED。
2. 视觉：
   同一面板正文同字号；标题有稳定层级；中文可读且完整，不能通过裁掉/漏画长段“通过”。检查截图中的残留英文及其实际归因。
3. 通用性：
   至少覆盖长短技能简介、不同职业、当前/下一级同时出现、装备属性、任务长正文和人物字段。示例只是测试，不是运行时特例。
4. 比例：
   Windows100%/125%/150%/200%显示缩放、游戏窗口比例、同内容重复F8。无额外OCR/AI调用；正文在同一尺度下仅容许合理取整差异，不可随译文长度逐块缩小。
5. 保护：
   图标、分隔线、物品数量、属性数值、正负号和百分比完整保留；面板外像素不受影响，当前/下级效果不会被正文覆盖。
6. 证据：
   返回源码diff、提交SHA、EXE SHA-256、构建输入记录、命令/退出码、原生字体度量及前后对照。Linux逻辑或合成像素结果不能替代Windows GDI和游戏视觉检查。
7. 云端验收：
   PASS / NEEDS_CHANGES / BLOCKED；未测项目单列。无需因原有发布授权重复索要确认；修改既有发布标签/资产前必须遵守不可覆写规则，修复应使用新版本。
