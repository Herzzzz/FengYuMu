# 桌面端 5.6 接管指令

任务号：CHAT-001。用户指定三方协作：云端负责分析、下发要求和最终验收；桌面端5.6负责转交与收集；DeepSeek Harness（DSH）负责实施。

用户确认以前已经建立过与 DeepSeek Harness 沟通的桥。请优先定位并复用旧桥，不自行安装替代桥，不覆盖已有配置。

1. 在当前项目工作区和已知的 Harness 工作目录中，查阅 AGENTS.md、桥接说明及 dsh/deepseek/bridge/relay 启动脚本。不要读取或回传密钥内容。
2. 报告桥的路径、原有启动命令、Harness版本、共享项目路径，以及当前是否连接。只报告非敏感地址和状态；认证材料保持在原配置中。
3. 从本协作分支读取 INSTRUCTIONS.md，并参考 CLOUD-REPRODUCTION.md。确认代码基线，创建 DSH 实施分支。定位桥成功后才转交任务。
4. 原样把任务交给 DeepSeek Harness。不得把“文件已准备”报告为“DSH已收到”。记录真实的投递和接收状态。
5. 收集 DSH 提交及自测，按 RESULT-TEMPLATE.md 回传。Windows实机检查由具备本机能力的一方执行，回传对应EXE哈希与实际结果。
6. 将实施提交SHA、结果文件路径和测试证据索引返回当前云端对话；也可提交到同一仓库的实施分支并返回分支名。云端将据此读取并验收。
7. 云端当前不能直接读取桌面私有目录；若旧桥只在本机工作，由桌面端承担转交，不要求用户复制数百行内容。未建立云端连接前，不宣称已经自动联通。

若定位失败，只回传已查找的项目范围和缺失信息。不得猜造端口、桥地址、CLI参数或宣称投递成功。
